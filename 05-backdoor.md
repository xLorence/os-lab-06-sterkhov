# Отчет по заданию 5 (Поиск и обезвреживание бэкдора)

**1. Полный вывод команды `find` с обнаружением подозрительного файла:**
```
/home/daniil247/demobash
/usr/bin/gpasswd
/usr/bin/mount
/usr/bin/pkexec
/usr/bin/ntfs-3g
```

### 2. Почему именно demobash подозрителен, а passwd и sudo — нет:

Системные утилиты вроде `passwd` и `sudo` лежат в стандартных системных каталогах (например, `/usr/bin/`) и по своей природе обязаны иметь `SUID` для выполнения административных задач. Наличие же исполняемого файла с SUID-битом от `root` в обычной пользовательской директории (`/home/daniil247/demobash`) — это явная аномалия и классический признак бэкдора, оставленного для несанкционированного повышения привилегий.

### 3. Доказательство опасности:

При запуске команды  `sudo -u student2 ~/demobash -p -c 'whoami; id'` вывод показал:

`rootuid=1001(student2) gid=1001(student2) euid=0(root) groups=1001(student2)`

Это доказывает, что обычный пользователь `student2`, запустив этот файл, мгновенно получил права суперпользователя `(root)`.

### 4. Обезвреживание:
Был выполнен сброс SUID-бита командой  `sudo chmod -s ~/demobash`.
Проверка с помощью `ls -l` подтвердила изменение прав на `-rwxr-xr-x` (буква s исчезла). Повторный запуск программы от имени `student2` показал, что `euid=0(root)` больше не появляется. После этого файл был удален командой `rm`.

### 5. Вывод (что должен делать администратор):
Администратор должен регулярно выполнять аудит системы командой `find / -perm -4000 -type f` и сравнивать полученный список SUID-программ с эталонным списком "чистой" системы. Любые новые или неизвестные файлы с битом `SUID`, особенно вне системных каталогов, должны немедленно проверяться и обезвреживаться.
